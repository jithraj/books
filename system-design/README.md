# System Design

A reading list for learning how to design reliable, scalable, and maintainable systems. Use publisher pages, bookstores, or libraries to access these books legally; this repository does not host book files.

## Start here

1. **Designing Data-Intensive Applications** — Martin Kleppmann. A deep foundation in data models, storage, replication, partitioning, and stream processing. [Publisher](https://www.oreilly.com/library/view/designing-data-intensive-applications/9781491903063/)
2. **System Design Interview – An Insider’s Guide** — Alex Xu. A practical introduction to breaking down and communicating system-design interview problems. [Publisher](https://www.bytebytego.com/guides/system-design-interview)

## Further reading

- **System Design Interview – An Insider’s Guide: Volume 2** — Alex Xu. More practice problems and design discussions. [Publisher](https://www.bytebytego.com/guides/system-design-interview)
- **Release It!: Design and Deploy Production-Ready Software** — Michael T. Nygard. Production resilience, failure modes, and stability patterns. [Publisher](https://pragprog.com/titles/mnee3/release-it-third-edition/)
- **Building Microservices** — Sam Newman. Microservice architecture, deployment, and operations. [Publisher](https://www.oreilly.com/library/view/building-microservices-2nd/9781492034018/)
- **Fundamentals of Software Architecture** — Mark Richards and Neal Ford. Architectural styles, trade-offs, and decision-making. [Publisher](https://www.oreilly.com/library/view/fundamentals-of-software/9781492043447/)

## Suggested study order

1. Learn core distributed-systems concepts with *Designing Data-Intensive Applications*.
2. Practice requirements gathering, capacity estimates, API design, and architecture diagrams with the interview guides.
3. Study operational reliability and architecture trade-offs with *Release It!* and *Fundamentals of Software Architecture*.
4. Review the system’s bottlenecks, failure scenarios, and trade-offs whenever you work through a design exercise.
